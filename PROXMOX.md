# Proxmox VE Microservices Integration Plan

## Goal

To deploy a suite of synrc Erlang-based microservices as lightweight, Alpine-based LXC containers or VMs within Proxmox VE. These services will provide infrastructure enhancements for Proxmox, including authentication (LDAP), Public Key Infrastructure (CA), encrypted software-defined networking (VPN), identity & authentication services (IAS), and a key-value store (KVS) that can be utilized as a Ceph metadata backend.

## Repositories Analyzed

1. `../../synrc/ca`
2. `../../zencrypted/vpn`
3. `../../zencrypted/ias`
4. `../../synrc/kvs`
5. `../../synrc/ldap`

All repositories are Erlang/Elixir applications. They can be compiled into standard Erlang OTP releases and packaged into minimal Alpine Linux images.

## Architectural Overview

Each service will be packaged as a standalone Alpine Linux image containing:
* Erlang/OTP runtime (via Alpine packages, e.g., `erlang`, `erlang-crypto`, `erlang-ssl`).
* The compiled OTP release (built via `rebar3 release` or `mix release`).
* A minimal supervision mechanism (e.g., `runit` or simply running the OTP release foreground script).

These images can then be deployed to Proxmox VE as:
* **LXC Containers:** Utilizing Proxmox's native container support for near-zero overhead.
* **VMs:** Using `qemu-img` to create QCOW2 images with a minimal seL4 kernel and VirtIO drivers.

## Implementation Steps

### 1. Build Standardized Alpine Dockerfiles

For each repository, we will create a multi-stage `Dockerfile` (or build script) to produce the Alpine image.

```dockerfile
FROM alpine:3.19 AS builder
RUN apk add --no-cache erlang erlang-public-key erlang-ssl erlang-crypto rebar3 git
WORKDIR /build
COPY . .
RUN rebar3 release
FROM alpine:3.17
RUN apk add --no-cache erlang-crypto erlang-ssl erlang-public-key
WORKDIR /opt/service
COPY --from=builder /build/_build/default/rel/service .
CMD ["/opt/service/bin/service", "foreground"]
```

### 2. Proxmox LXC Template Creation

To provide these as native Proxmox VE services, the Docker images can be exported to rootfs tarballs, which Proxmox uses as LXC templates:
```bash
docker export $(docker create synrc-ldap:alpine) > synrc-ldap-alpine.tar
pct create 101 local:vztmpl/synrc-ldap-alpine.tar --arch amd64 --hostname synrc-ldap --net0 name=eth0,bridge=vmbr0,ip=dhcp
```

### 3. Service Integration Points in Proxmox

* **LDAP & IAS (`synrc/ldap`, `zencrypted/ias`):**
  Configure a Proxmox Custom Authentication Plugin (`/usr/lib/pve-auth/`) that hooks into these Alpine containers to provide ABAC (Attribute-Based Access Control) authentication for the Proxmox Web UI and API.
  * **API Protocol:** HTTPS JSON-RPC
  * **Core Methods:** `bind(User, Password)`, `search(Filter)`, `check_group(User, Group)`
  * **Proxmox API Spec:** [Proxmox Access API](https://pve.proxmox.com/pve-docs/api-viewer/index.html#/access)

* **CA (`synrc/ca`):**
  Act as a centralized certificate authority. The Alpine container exposes an API to sign CSRs generated by Proxmox nodes and VMs.
  * **API Protocol:** HTTPS JSON-RPC
  * **Core Methods:** `sign_csr(CSR, Options)`, `list_templates()`
  * **Proxmox API Spec:** [Proxmox Certificates API](https://pve.proxmox.com/pve-docs/api-viewer/index.html#/nodes/{node}/certificates/custom)

* **VPN (`zencrypted/vpn`):**
  Provides encrypted SDN overlays. The container can attach a virtual network interface (veth) to a Proxmox bridge (e.g., `vmbr1`), creating a secure tunnel between Proxmox nodes or VMs.
  * **API Protocol:** HTTPS JSON-RPC (Management) / Zencrypted Protocol or WireGuard (Data Plane)
  * **Core Methods:** `create_tunnel(ClientId, PeerId, Options)`, `list_tunnels()`, `delete_tunnel(TunnelId)`
  * **Proxmox API Spec:** [Proxmox SDN API](https://pve.proxmox.com/pve-docs/api-viewer/index.html#/cluster/sdn)

* **KVS (`synrc/kvs`):**
  Acts as a metadata store for Ceph. The Alpine KVS container provides an ETS/Dets backed datastore. Ceph's RADOS Gateway can be configured to use this KVS via an API endpoint.
  * **API Protocol:** HTTPS JSON-RPC or S3-Compatible REST
  * **Core Methods:** `put(Key, Value)`, `get(Key)`, `delete(Key)`, `list(Prefix)`
  * **Proxmox API Spec:** [Proxmox Ceph API](https://pve.proxmox.com/pve-docs/api-viewer/index.html#/storage)

### 4. Verification Plan
