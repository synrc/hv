# NIST SP 800-53 Control Mapping Rationale

Synrc Hypervision (OS.1) leverages seL4 capability security and Microkit static configuration to satisfy key security control families specified in NIST SP 800-53.

## Control Mapping Summary Table

| Control Family | Example Controls | Hypervision Technical Implementation Rationale |
| :--- | :--- | :--- |
| **AC** Access Control | AC-3, AC-4, AC-6 | seL4 capability model and Microkit static channel definitions enforce least privilege and information-flow bounds. Zero ambient authority exists at runtime. |
| **AU** Audit & Accountability | AU-2, AU-12 | Dedicated `Monitor` PD collects system events, audit records, and health metrics over explicit notification channels into an isolated memory region. |
| **CM** Configuration Management | CM-2, CM-6, CM-7 | System topology (PDs, channels, memory regions, core affinities) is immutably defined at build time in Microkit `.system` XML files. Unused components are compiled out (`MONITOR=0`, `NET=0`). |
| **SC** System & Comms Protection | SC-7, SC-39 | Microkit provides spatial isolation via page tables and temporal isolation via seL4 MCS scheduling contexts, preventing resource starvation or side-channel leakage. |
| **SI** System & Information Integrity | SI-7, SI-16 | Reproducible compilation scripts produce static, deterministic `loader.img` boot artifacts with immutable capability layouts. |
| **CP** Contingency Planning | CP-9, CP-10 | Erlang/OTP supervision trees inside `Tyn` provide deterministic process recovery. seL4 contains any unhandled fault strictly within the originating protection domain. |
| **IA** Identification & Authentication | IA-2, IA-5 | Can be realized as a dedicated authentication protection domain that guards capability channels before external connection setup. |
| **SA** System & Services Acquisition | SA-11, SA-15 | Minimal Trusted Computing Base (TCB) consisting solely of seL4 microkernel (~10k LOC) and Tyn syscall trap host, completely isolating driver complexity. |

---

## Build Flag Controls

Compile-time options directly govern control enforcement:
- `SECURITY=nist53`: Enables strict capability checking and audit event emission.
- `MONITOR=1`: Compiles in the `Monitor` PD for AU-2 audit compliance.
- `BOARD=qemu_virt_aarch64` / `BOARD=rpi4b_8gb`: Configures hardware memory boundaries and peripheral access capabilities.
